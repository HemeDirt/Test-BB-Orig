# СТАРТ ЧАТА С КОДЕРОМ: пошаговая инструкция с нуля

*Собрано 2026-11 под вашу ситуацию: есть репозиторий GitHub Test-BB-Orig, есть локальная папка
G:\BB\Test-BB-analysis-of-the-game-project-6f8d2 с наследством прошлых чатов и рабочей симуляцией
бота, есть платформа с блоком «Code execution» при привязке. Цель — начать чат так, чтобы агент
сразу работал правильно и ничего не потерялось.*

## 1. Что такое блок «Code execution» при привязке

Это настройка КОМНАТЫ, в которой агент будет исполнять код, а не про вас и не про проект.
- **Переменные среды** — пары «имя = значение», которые платформа подставит в окружение комнаты
  (обычно для ключей API и паролей). Для нашего проекта **оставить пустым**: симулятору не нужны
  секреты, а ключи туда всё равно класть не стоит.
- **Скрипт установки** — команды, которые платформа выполнит ОДИН раз при старте комнаты
  (обычно установка библиотек). Наша симуляция — чистый Python без библиотек, поэтому достаточно
  одной проверочной строки или пустого поля:
  `python3 --version`
  Если позже симулятору понадобится библиотека, сюда дописывается строка вида `pip install numpy`.
Вывод: этот блок не трогает ваши файлы и не влияет на правила агента. Правила агента живут в
QWEN.md репозитория и в первом сообщении чата.

## 2. Что такое репозиторий и привязка простыми словами

Репозиторий GitHub — это папка в облаке с историей изменений. Привязка чата к репозиторию значит:
агент получает копию этой папки в свою комнату, работает в ней, а результаты можно забрать обратно
(push) или скачать zip-ом с сайта. Branch «main» — главная ветка, теги и pull requests нам не нужны.
Важно: агент видит ТОЛЬКО то, что лежит в репозитории. Всё, что осталось у вас на диске вне
репозитория, для него не существует. Поэтому состав репозитория = состав проекта.

## 3. Чистый состав проекта: что класть, что не класть

Класть (код, данные, документы):
- Корень: `QWEN.md` (standing-правила), `SPEC.md` (спецификация симуляции), `DECISIONS.md`,
  `STATE.md` (можно пустые с заголовками), `README.md` с картой папок.
- `sim/` — код рабочей симуляции бота (то, что запускает партию: bb_core/bb_full или sim*.py,
  матрицы, валидатор). Это ядро проекта.
- `data/` — колоды и пулы: txt категорий (1_professiya … 11_obmen), pool_sim1000.json,
  pool_indices.json, final_v5.json, deck-записи, печатный набор карт.
- `docs/` — правила печати, памятка, справочник, журнал чистки, отчёты симуляций, этот протокол.
- `results/` — пустая папка с файлом .gitkeep: сюда агент пишет json прогонов.

Не класть (мусор и риски):
- html-файлы и папки site_live, site_v11, site_v9_final, webtest, blitz, main_backup — это побочные
  сборки, они путают агента и съедают его контекст.
- Все zip-архивы (blitz_new_site.zip, site_package.zip, Test-BB-site.zip, workspace.tar.gz и др.):
  агент не должен их распаковывать; держите их ВНЕ репозитория как личный архив.
- Дубликаты файлов с суффиксами (1), (2): оставить по одной копии.
- package.json / package-lock.json / .nojekyll / index.html — от веб-проектов, не от симуляции.
- chat-export-*.json можно положить в docs/archive/ одним файлом, если жалко расстаться.

Правило отбора одним предложением: в репозиторий идёт только то, что агенту разрешено читать и
менять; всё сомнительное живёт вне и достаётся вручную по необходимости.

## 4. Подготовка локально (10 минут)

1. Создать новую папку, например `G:\BB\Test-BB-Orig\`, и собрать в ней состав из раздела 3
   копированием из старой папки (не переносом: старое пусть лежит как есть до первой удачи).
2. Положить в корень файлы из этой рабочей области: `QWEN_MD_ПРАВИЛА_ПРОЕКТА.md` сохранить как
   `QWEN.md`, `ЗАДАНИЕ_НА_СИМУЛЯЦИЮ_ББ.md` как `SPEC.md`, `ПРОТОКОЛ_РАБОТЫ_С_QWEN_CODER.md` в docs/.
3. Создать пустые `DECISIONS.md` и `STATE.md` с одной строкой-заголовком в каждом.
4. Проверить ядро ДО привязки: в папке sim/ найти запускаемый файл и выполнить в консоли
   `python3 bb_full.py 1 8` (или имя из вашей симуляции). Должен напечататься лог партии.
   Если не запускается — чинить до привязки, а не после: агент не должен стартовать на битом ядре.
5. Сделать zip-копию всей папки ВНЕ неё (например G:\BB\backup_start.zip).

## 5. Загрузка в GitHub без умения git

Вариант А (проще, через сайт): на странице репозитория «Add file → Upload files», перетащить файлы
и папки из шага 4 (сайт принимает до 100 файлов за раз; папки перетаскиваются целиком), затем
«Commit changes». Повторить партиями, если файлов больше ста.
Вариант Б (если git уже стоит): в консоли из папки проекта:
`git init` → `git add .` → `git commit -m start` → `git branch -M main` →
`git remote add origin https://github.com/HemeDirt/Test-BB-Orig.git` → `git push -u origin main`
(первый push спросит логин и токен доступа вместо пароля; токен создаётся на сайте в
Settings → Developer settings → Personal access tokens, галочка repo).
После любого успешного шага проверить на сайте: файлы видны в списке репозитория.

## 6. Привязка чата и первое сообщение

1. При привязке выбрать репозиторий Test-BB-Orig и ветку main. Блок Code execution: переменные
   пустые, скрипт установки `python3 --version` (или пусто).
2. Первым сообщением вставить дословно:

«Прочитай в корне QWEN.md и SPEC.md и работай по ним весь чат. Затем: выведи список файлов
репозитория; запусти одну партию симуляции из папки sim с сидом 1 и N=8 и покажи последние 20 строк
лога и строку STATS; создай STATE.md с описанием текущего состояния кода (какие файлы есть, что
запускается, что сломано). Код в этом сообщении не меняй совсем. Закончи одним вопросом ко мне,
если что-то в QWEN.md или SPEC.md непонятно.»

3. Дождаться выполнения и проверить глазами: лог напечатан, STATE.md появился, вопросов не больше
   одного. Только после этого начинать этап 1 контракта (ядро) и дальше по этапам.

## 7. Правила безопасности на весь чат

- После каждой приёмки этапа: коммит на сайте («Commit changes») или `git commit` локально, плюс
  раз в день скачивать zip репозитория кнопкой Code → Download ZIP. Это ваши точки отката.
- Если агент предложил удалить файл, перенести проект, скачать что-то или настроить окружение вне
  папки — ответ «нет, пункт 2 контракта» и возврат к QWEN.md.
- Если агент «изменил», но вывода запуска нет — считать несделанным и просить вывод.
- Если чат начал путаться или повторяться — это переполнение контекста: попросить записать STATE.md
  и DECISIONS.md, затем начать новый чат с тем же репозиторием: QWEN.md подхватится сам.
